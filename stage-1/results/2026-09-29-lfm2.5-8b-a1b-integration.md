# LFM2.5-8B-A1B TikZ LoRA integration — 2026-09-29

This is an implementation record, not a training result. It adds an isolated
native Stage 1 path for `LiquidAI/LFM2.5-8B-A1B`, pinned at Hub revision
`5dd22602c2e9f6a097b1de4c4efe0658b605015c`.

## Scope

- Architecture: text-only `Lfm2MoeForCausalLM`, 8.3B total parameters and
  1.5B active parameters, 24 hybrid convolution/GQA layers, 32 experts with
  four selected per token, and a 128,000-token declared context.
- Training: unquantized BF16 LoRA through Unsloth `FastLanguageModel`; Stage 1
  remains capped at 8,192 prompt-plus-target tokens.
- Template: pinned LFM ChatML boundaries with direct TikZ assistant targets.
  The reasoning-tuned base is not given synthetic hidden reasoning, and
  assistant-only loss masking remains exact.
- LoRA targets: `q_proj`, `k_proj`, `v_proj`, `out_proj`, `w1`, `w2`, and
  `w3`. Unsloth is expected to detect sparse expert parameters from the MLP
  targets; the strict post-attachment check must prove the resulting adapter.
- Runtime isolation: separate config, adapter slug, dependency lock, prepared
  dataset directory, standalone Python launcher, Slurm wrapper, and run root.

## Required validation

1. Download and resolve the exact pinned snapshot.
2. Prepare a fresh `lfm25-8b-a1b` tokenizer dataset and verify its report.
3. Run `overfit-100`; require finite gradients, target loss, final artifact,
   and checkpoint creation.
4. Run an explicit checkpoint resume drill.
5. Run `smoke-1000` before any full-data allocation.
6. Start the one-epoch full gate only after all prior evidence passes.

No GPU job, model load, tokenizer preparation, or training run was performed
while adding this integration. Transformers 5.5 compatibility, Unsloth's MoE
expert attachment, VRAM use, throughput, serialization, and resume behavior
are therefore **GPU unverified**.
